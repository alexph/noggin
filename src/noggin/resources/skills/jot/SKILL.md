# Jot

Read `noggin/index.md` and [memory conventions](../noggin/references/memory.md).
Read only the matching [templates](../noggin/templates/) for candidate updates.
If noggin is absent, explain how to initialize it before capturing memories.

Review the current session and relevant code changes or verification results.
Extract facts worth retaining: discoveries that affect future work, explicit
decisions and their reasons, completed outcomes, useful failed approaches, and
unfinished commitments. Separate observations from hypotheses. Do not claim
access to turns lost from context or reconstruct missing details as facts.

Compare candidates with existing memory. Update a subject's existing wiki page,
record completed work in the ledger, and attach unfinished work to a plan.
Change vision only when project direction was actually decided. Record a
principle only when there is evidence for a durable rule, with proposed status
for unestablished candidates.

Use templates, include supporting references, and maintain semantic indexes.
Skip duplicate, transient, or unsupported material. Do not save a transcript or
record credentials. If nothing useful has changed, make no edits.

Report the files updated and any uncertain candidates left out. Capturing
memory does not authorize unrelated code changes, commits, or external actions.
